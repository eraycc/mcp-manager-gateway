# 安全模型

MMG 管理的配置可能启动本地进程、访问网络、读取文件或修改业务系统。MCP 配置应视为管理员权限，网关不能把不受信任的程序自动变成安全程序。

## 权限层级

有效权限是多层交集：

1. 服务是否启用；
2. 用户是否获授权；
3. Token 是否包含目标服务；
4. 工具过滤是否允许；
5. OAuth 或服务凭据是否可用；
6. 调用参数是否符合 Schema；
7. 运行时是否允许当前实例范围。

任何一层失败都应拒绝，而不是退回匿名或更宽权限。

## Token

- 普通用户只能管理自己的 Token；
- Token 可以使用固定服务集合或跟随用户的全部授权；
- 无效 Token 不会自动降级为匿名；
- 管理员提议权限应临时开启并在迁移后撤销；
- 不把 Token 写进 URL、代码仓库或日志；
- 轮换暴露或长期不用的 Token。

## Agent 提议审批

Agent 提议只进入审批队列，不能直接执行。审批者负责设置运行模式、实例隔离和 OAuth 配置隔离，并真实测试审批后的配置。

提议中不要提交真实密钥。使用环境变量名或在控制台的敏感字段中补齐。

## OAuth

个人 OAuth 按用户隔离：

- 每位用户独立授权；
- 凭据、能力目录和实例按用户区分；
- 一位用户授权过期不应影响其他用户；
- 服务模式不能伪装成个人数据隔离。

`PUBLIC_URL` 必须与 OAuth 提供方回调配置一致。生产环境使用 HTTPS 与安全 Cookie。

## 实例隔离

共享实例只适合允许共享下游状态的服务。浏览器、账号会话、个人文件等有状态服务优先使用用户或会话隔离。

网关 Token 隔离不等于下游业务系统自动隔离。若下游使用同一账户，其业务数据仍可能共享。

## 日志与审计

- 普通用户只能查看自己的调用记录；
- 管理员可按用户审计；
- 不在错误响应中返回秘密配置；
- embedding 仅接收描述性目录元数据；
- 设置合理日志保留期；
- 备份与导出继续按敏感数据管理。

## 副作用与重试

调用发出后连接断开时，结果可能未知。标记 `outcome_unknown` 后禁止自动重放写操作。需要先到业务系统核对实际结果，再由人决定是否重试。

## 部署建议

- 使用专用低权限账户；
- 不同信任域使用不同部署或容器；
- 限制可执行命令与可访问目录；
- 使用 HTTPS、防火墙和 Host/CORS 限制；
- 定期轮换 Token 与 OAuth secret；
- 保留数据库和根密钥的加密备份。
