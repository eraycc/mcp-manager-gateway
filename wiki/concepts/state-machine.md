# 状态机：启动策略、运行状态与隔离

> 本文是 MMG（MCP Manager Gateway）运行时状态的**规范定义**，不是教程。
> 任何涉及 `mode`、运行状态、`isolation` 的代码、接口与文档，都应以此页为准。
> 修改状态语义时，必须同步更新本页与文末“不变量”清单。

---

## 1. 概述

MMG 的状态不是单一枚举，而是由三个**正交维度**共同决定：

| 维度 | 字段 | 回答的问题 |
|---|---|---|
| 启动策略 | `mode` | 这个 MCP **该不该被拉起、该不该保持运行** |
| 运行状态 | `state` | 这个 MCP **此刻是什么状态** |
| 隔离策略 | `isolation` | 这份状态、凭据、缓存**归谁所有** |

任何一条规则，都必须同时回答这三个问题。只盯一个维度、忽略另外两个，是 MMG 历史上多数状态类缺陷的根因（例如“停止”被误当作“禁用”，污染了刷新链路）。

三个维度相互独立：

- `mode` 决定**意图**（想不想跑）；
- `state` 决定**现实**（现在跑没跑）；
- `isolation` 决定**归属**（这份现实属于谁）。

---

## 2. 维度定义

### 2.1 启动策略（`mode`）

| 值 | 语义 | 拉起时机 | 空闲回收 | 调用准入 |
|---|---|---|---|---|
| `lazy`（按需） | 有调用才拉起 | 调用触发 | 允许回收 | 允许 |
| `eager`（常驻） | 拉起后保持运行 | 启用/首次调用后常驻 | 不因空闲回收 | 允许 |
| `disabled`（禁用） | 拒绝调用、跳过刷新、个人资料不可见 | 不拉起 | 不适用 | **拒绝** |

要点：

- **`disabled` 是唯一的“全局关闭”开关**。它同时作用于：调用准入、定时刷新、个人资料可用服务列表。
- `disabled` **保留**凭据与缓存（可逆），不执行删除级联清理。
- `lazy` / `eager` 的区别只在“是否常驻”，**都不阻止调用**。

### 2.2 运行状态（`state`）

| 值 | 语义 | 是否可被调用拉起 | 自动恢复 |
|---|---|---|---|
| `starting` | 启动中 | 过渡态，等待或返回“启动中” | 就绪后转 `ready` |
| `ready` | 已启动可用 | — | — |
| `stopped` | 已停止（手动停止 / 空闲回收 / 禁用落地） | **可以**（`lazy`/`eager` 下次调用重新拉起） | 调用或定时刷新 |
| `failed` | 连续连接 / 启动 / 目录发现失败达到阈值 | 授权后的精确调用可先恢复目录，再校验并执行 | 精确调用、定时或手动刷新 |

要点：

- **`stopped` 只是“当前没在跑”，不是“不许跑”**。手动停止 = 强制结束当前实例，不改变策略、不阻止后续调用。
- **`failed` 表示连续失败达到阈值**：默认 3 次，仅连接、启动和目录发现失败计数；工具业务报错与响应校验错误不计数；达到阈值才置空该归属目录并记录原因。未达阈值保留最后成功目录。
- 定时或手动刷新、授权后的精确调用前目录恢复都可验证恢复；业务调用不重放。
- 恢复成功（任一路径）→ 清除 `failed` 标记与失败计数、重建能力缓存。

### 2.3 隔离策略（`isolation`）

| 值 | 适用 | 凭据归属 | 缓存 key 维度 | 失败计数维度 |
|---|---|---|---|---|
| `service`（服务共享） | HTTP / stdio | 服务级一份，管理员维护 | `server_id` | 服务级 |
| `user`（按用户隔离） | HTTP 为主 | `(server_id, owner)`，每人一份 | `(server_id, owner)` | 按 `owner` 各自计 |
| `session`（按会话隔离，stdio 专有） | stdio | 随会话，不持久化 | 随会话 | 随会话，结束即清 |

要点：

- **隔离维度决定“这份状态归谁”**：凭据、缓存、失败计数、运行时实例都必须按隔离维度分叉。
- `user` 隔离下，**用户 A 的失败不影响用户 B**；A 的凭据与缓存只属于 A。
- `session` 隔离下，**不落持久凭据与缓存**，会话结束即清。
- 缓存 key **必须携带隔离维度**，否则会出现跨用户串缓存。

## 3. 模式 × 状态矩阵

| `mode` \ `state` | `starting` | `ready` | `stopped` | `failed` |
|---|---|---|---|---|
| **`lazy`** | 调用触发拉起中；可等待或返回“启动中” | 正常调用；空闲后回 `stopped` | 调用触发重新拉起 | 调用直接返回 `failed` + 原因；不自动拉起；定时刷新兜底 |
| **`eager`** | 启动中，就绪后**保持运行** | 保持运行 | **异常态**：`eager` 承诺常驻，应尽快恢复为 `ready`（调用或定时刷新） | 同 `lazy`：不自动重试；恢复后保持运行 |
| **`disabled`** | **非法**（禁用不得启动） | **非法**（若存在应被强制停止） | **合法终态**：已停且禁用 | **合法终态**：禁用后不再尝试 |

说明：

- `disabled` 与 `starting` / `ready` 同现属于**不一致状态**：将 `mode` 设为 `disabled` 时必须先停止实例，状态落 `stopped`。
- `eager × stopped` 是**异常态**：常驻承诺被打破，应标记并在下次调用/定时刷新时强制拉起。
- `failed` 在 `lazy` / `eager` 下行为一致：调用不触发自动拉起，自动恢复仅定时刷新。

---

## 4. 隔离 × 行为矩阵

| 行为 | `service` | `user` | `session`（stdio） |
|---|---|---|---|
| 凭据归属 | 服务级一份 | `(server_id, owner)` | 随会话，不持久 |
| 缓存 key | `server_id` | `(server_id, owner)` | 随会话 |
| 失败计数 | 服务级 | 按 `owner` 各自计 | 服务级，随共享目录归属 |
| `failed` 影响范围 | 全体 | 仅该 `owner` | 仅该会话 |
| 禁用影响 | 全体不可用 | 全体不可用（个人资料隐藏） | 会话终止 |
| 删除清理 | 服务级凭据 / 缓存 | 全部 `owner` 的凭据 / 缓存 | 会话资源 |

要点：

- **失败隔离**：`user` 隔离下，某用户连续失败只标记该用户，**不影响其他用户正常调用**。
- **定时刷新**：对 `lazy` / `eager` 的 `user` 隔离 MCP，定时任务刷新**全部用户**的能力缓存；`disabled` 才整体跳过。
- **禁用 / 删除语义**：
  - **禁用**：保留凭据与缓存（可逆），仅拒绝调用、跳过刷新、个人资料隐藏。
  - **删除**：级联清理所有 `owner` 的凭据、能力目录记录、授权引用与相关缓存；定义文件可后台宽限回收，但服务在列表/调用/刷新中**立即不可见**。

---

## 5. 失败与恢复语义

### 5.1 失败计数

- 失败计数按**目录归属**记录：服务共享及 stdio 会话实例隔离共用服务目录计数；按用户隔离使用 `(server_id, owner)`。
- 调用与手动、定时目录刷新共用计数；**有效工具响应（包括业务报错）或完整刷新成功即清零**计数及失败状态。连接成功和 OAuth Token 续期本身不清零；最近一次刷新警告可作为历史保留。
- 计数是“**连续次数**”语义，不按天计算；内部连接、续期、重试只按一次逻辑操作的最终结果计数。
- 重配凭据后，该 `owner` 的失败计数清零（新凭据不应沿用旧失败数）。

### 5.2 达到设置阈值进入 `failed`

- 第 1~2 次失败：**只记计数与原因，不动能力缓存列表**。
- 连续失败达到设置阈值（默认 3 次）：
  - 标记 `failed`；
  - **清空该归属维度的能力缓存列表**；
  - 记录失败原因（供 UI 与调用方查看）。
- `failed` 期间：
  - 已授权的精确调用可先恢复目录、重新校验定义再执行；不会重放已执行或结果不明的业务调用；
  - 定时、手动刷新仍可继续尝试。

### 5.3 恢复

- 恢复成功（定时刷新 / 人工修复 / 重配凭据后刷新）→ 清除 `failed` 标记与失败计数、重建能力缓存。
- OAuth 场景：刷新成功但授权失效**不视为恢复**，仍标记“授权失效”，需用户重新授权。

## 6. 刷新语义

- **刷新是维护动作，不是业务调用**：它需要拉起下游进程以重新发现能力。
- 纯搜索、目录分页不启动下游；已授权的精确调用在目录缺失时可以先发现并校验当前定义，随后只执行一次业务调用。
- 触发源：
  - **手动刷新**（管理员服务列表 / 用户在凭据弹窗刷新本人缓存）；
  - **定时刷新**（后台异步、有并发上限，按 `disabled` 过滤，`lazy`/`eager` 均尝试）；
  - **人工修复后刷新**。
- 用户级手动刷新：
  - 仅对 `isolation=user` 且需要认证的 HTTP 类 MCP；
  - 入口在“配置凭据 / OAuth 授权”弹窗内；
  - **必须已保存本人凭据**（OAuth 还需完成本人授权）才可执行；
  - **只刷新当前登录用户自己的缓存**，身份只来自会话，不接受指定他人；
  - 刷新失败只落该 `owner` 的失败状态与原因，允许再次刷新，不影响他人。

## 7. 不变量（Invariants）

以下不变量是 MMG 状态机的硬约束，代码、接口、测试均应以编号引用（如 `# INV-2`）。

- **INV-1**：`disabled` 必须落 `stopped`，**不得**与 `starting` / `ready` 同现。
- **INV-2**：允许授权后的精确调用恢复缺失目录；已开始或结果不明的业务调用不得自动重放。
- **INV-3**：`stopped` 只是“当前未运行”，**不得**被解释为“禁止调用”；手动停止不改变 `mode`、不设置任何阻断调用的标记。
- **INV-4**：`disabled` 是**唯一**同时作用于“调用准入 + 定时刷新 + 个人资料可见性”的全局开关。
- **INV-5**：缓存按目录归属隔离（服务共享及 stdio 会话实例隔离 → 服务；`user` → `(server_id, owner)`）；运行实例隔离不改变凭据与目录归属。
- **INV-6**：失败计数与 `failed` 标记**必须**按隔离维度归属；`user` 隔离下 A 的失败不得影响 B。
- **INV-7**：有效工具响应（包括业务报错）/ 完整刷新必须清零对应归属的失败计数；仅连接或续期成功不清零，未达阈值不清空最后成功目录。重配凭据不沿用旧凭据的失败数。
- **INV-8**：`session` 的运行实例按租期隔离，不跨租期复用；其凭据和能力目录仍采用服务归属。
- **INV-9**：删除服务**必须**级联清理所有归属维度的凭据与缓存；禁用**不得**执行该清理。

## 8. 特殊与非法组合

| 组合 | 判定 | 处理 |
|---|---|---|
| `disabled` × `starting` / `ready` | **非法** | 设 `disabled` 时先停实例，落 `stopped` |
| `eager` × `stopped`（长期） | **异常** | 标记异常，下次调用/定时刷新强制拉起 |
| `failed` × `lazy` / `eager` | 合法 | 精确调用、定时或手动刷新可验证恢复 |
| `session` × 服务凭据/目录 | 合法 | 仅运行实例按租期隔离 |
| `failed` 期间精确调用先恢复目录 | 合法 | 只读发现完成并校验后执行一次业务调用 |
