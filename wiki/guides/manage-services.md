# 服务管理与测试

[文档首页](../README.md) · [English README](../../README.md) · [简体中文 README](../../README.zh-CN.md)

本文是面向管理员的操作指南，说明服务列表、运行策略、实例隔离、凭据配置与测试的操作方式。
状态的完整语义（维度定义、交叉矩阵、不变量）见
[状态机：启动策略、运行状态与隔离](../concepts/state-machine.md)；本文只保留操作要点，不重复定义。

## 列表、能力摘要与配置导出

MCP 服务列表的“能力列表”显示缓存中的工具、资源、提示词和资源模板数量；点击“能力/测试”查看分页目录与测试入口。个人资料的“可访问的服务”同时显示服务描述（如有）和上述缓存数量。未建立缓存时不会把零数量显示为成功发现；浏览这些摘要不会启动下游服务。

按用户隔离且需要认证的 MCP，在管理员列表中单独显示“当前用户能力列表”或“当前用户未认证”；能力数量属于当前管理员，不复用其他用户的缓存。“已认证 n / m”的分母为有权访问该服务的启用用户（包含管理员），分子为已完整保存凭据的用户；OAuth 还须具有未过期或可续期的个人授权。能力发现失败不影响已配置人数，禁用账户和无服务访问权的用户不计入统计。

MCP 服务页顶部的“导出配置”位于“导入配置”和“新增服务”之间。确认后下载全部服务的 `mcpServers` JSON 配置，包括禁用的服务，不受当前分页、筛选或勾选影响。敏感字段默认脱敏，重新导入后需补齐凭据；格式见[配置导出](../reference/catalog-api.md#service-configuration-export)。批量工具栏中的“导出”仍只导出选中服务。

MCP 服务、MCP 审批、访问令牌、调用日志和用户管理列表支持跨页选择：

- 单行勾选和“选择当前页”可累积到其他页；上一页、下一页、跳页、调整每页条数及列表内刷新均保留选择。
- “选择全部筛选结果”选中当前筛选下的所有记录；“清空选择”取消所有页的选择。计数表示跨页选中总数。
- 更改搜索或筛选、离开当前列表或退出登录会清空选择；选择状态只保存在当前页面会话中。
- 批量操作接收全部已选 ID，并遵循接口限制分批提交。取消确认或执行失败保留选择，全部成功后清空；导出保留选择。

## 稳定标识

每个 MCP 有显示名称和稳定 `slug`。slug 参与工具路由，创建后不应修改。需要新标识时创建副本并逐步迁移。

原始工具通常映射为 `<slug>__<tool>`；名称过长或包含特殊字符时，MMG 会生成稳定短名称。调用时始终使用搜索结果中的精确 `gateway_name`。

## 运行策略

`mode` 表示启动策略，决定“该不该拉起、该不该保持运行”。完整语义与 `mode × state` 矩阵见
[状态机 · 模式 × 状态矩阵](../concepts/state-machine.md#3-模式--状态矩阵)。

| 模式 | 行为 |
| --- | --- |
| `lazy` | 第一次真实业务调用时启动；推荐默认值。空闲可回收。 |
| `eager` | 网关启动或具备身份上下文时预热；启动后保持运行。 |
| `disabled` | 拒绝调用、跳过定时刷新、从个人资料可用服务列表隐藏；保留凭据与缓存，可逆。 |

搜索目录和读取缓存不会为了 `lazy` 服务启动下游。

> 注意：`disabled` 是唯一的“全局关闭”开关（INV-4）。手动“停止”不是禁用，见下文“状态理解”。

## 实例隔离

`isolation` 决定凭据、缓存、失败计数和运行时实例的归属。完整矩阵见
[状态机 · 隔离 × 行为矩阵](../concepts/state-machine.md#4-隔离--行为矩阵)。

- **service**：授权用户共享实例，适合无个人状态的公共服务；凭据与缓存在服务级一份。
- **user**：同一用户的多个 Agent 复用，不同用户隔离；凭据、缓存、失败计数按 `(server_id, owner)` 各自独立。
- **session**（stdio 专有）：每个 Agent 会话独立，适合浏览器等强状态服务；不落持久凭据与缓存，会话结束即清。

个人 OAuth 凭据和能力目录按用户隔离。不要用管理员的 OAuth 缓存替代普通用户身份。用户 A 的失败不会影响用户 B（INV-6）。

## 添加后的发现

启用服务保存后，MMG 会运行能力发现并缓存：

- tools；
- resources；
- prompts；
- resource templates。

`lazy` 服务用于维护发现的临时实例会在完成后释放。实际 Agent 搜索读取缓存，不反复启动服务。

## 个人凭据配置与修改

管理员和普通用户都可以在“个人资料 → 可访问的服务”中配置自己的凭据。适用范围为按用户隔离的服务，支持全部内置认证类型：

- Bearer Token：填写或替换个人 Token。
- Basic：填写或修改用户名和密码。
- API Key：填写请求头名称（默认 `X-API-Key`）与个人 Key。
- OAuth：当 OAuth 配置隔离为“独享配置”时，使用统一四态下拉框选择预注册（Client ID 必填、Secret 可选）、优先 CIMD 且失败回退 DCR（新配置默认）、仅 CIMD 或仅 DCR，并修改端点和 Scopes；端点可自动发现。需要授权时使用“授权”入口。共享配置下各用户仍分别授权，注册客户端可按配置归属复用。详见 [OAuth 配置指南](oauth.md)。

凭据保存后，“配置凭据”或“OAuth 配置”入口继续保留，包括等待授权、发现中、可用或发现失败状态。再次打开可填写新凭据进行替换；此表单不回显已保存的秘密。修改只更新当前用户的凭据，并使该用户的旧运行实例和能力缓存失效，然后尝试重新发现，其他用户的凭据不受影响。重配凭据会清零该用户的失败计数（INV-7）。

无认证的服务不显示凭据编辑入口。服务共享凭据和 OAuth 共享配置仍由管理员在 MCP 服务配置中维护，普通用户不能从个人资料修改共享配置。旧版按用户隔离的 Basic/API Key 如果仅在服务配置内保存了凭据而没有个人归属记录，需在个人资料重新填写，系统不会将这类凭据当作其他用户的个人凭据复用。

### 手动刷新个人能力缓存

按用户隔离且需要认证的 Streamable HTTP、SSE、REST 服务，在个人凭据弹窗中提供“刷新能力缓存”；使用 OAuth 共享配置时，通过个人资料中的“授权”入口打开同一刷新功能。管理员和普通用户均可使用，仅刷新当前登录用户的能力，不修改其他用户或共享服务缓存。身份只来自会话，接口不接受指定他人（INV-6）。

先保存完整凭据；OAuth 还需完成有效授权，才可刷新。输入框中尚未保存的修改不会参与刷新。发现失败后可以再次刷新；**手动刷新、定时刷新和调用共用本人的连续失败计数**。未达阈值时保留上次成功目录与缓存时间并展示失败原因；默认连续 3 次失败才置空四类能力目录并标记 `failed`，任一次调用或完整刷新成功即清零。刷新过程中若权限、服务版本、隔离或禁用状态改变，旧结果不能发布。接口见[个人缓存刷新](../reference/catalog-api.md#个人能力缓存刷新)。

管理员禁用服务后，所有用户均无法再访问其旧能力目录，服务退出个人资料列表且不参与定时刷新；个人凭据保留供以后重新启用。删除服务会清理所有用户的凭据、授权记录及目录缓存；无引用的定义文件按存储保留期异步回收（INV-9）。

OAuth 令牌显示有效、已过期或需要重新授权。过期且有 Refresh Token 时，首次实际使用最多刷新一次；失败或下游 HTTP 401 后持久进入“需要重新授权”，后续调用不再刷新或自动重试。请明确点击“重新授权”，成功后重新发现能力。打开弹窗仅查询状态，不会注册客户端或发起授权。

## 敏感字段编辑

MCP 服务和 MCP 审批共用配置编辑器。Bearer Token、密码、API Key 与 Client Secret 等字段默认使用密码输入框并以掩码显示。点击“显示敏感字段”后，编辑器会在取得授权的完整配置后把对应输入框切换为普通文本，便于核对和修改；点击“隐藏敏感字段”会重新使用密码输入框和 `[REDACTED]` 占位，未修改的密钥仍由网关安全保留。

不要在截图、日志或问题报告中暴露显示后的真实值。

## 测试

诊断应真实连接下游并读取能力。工具测试可以保存显式参数用例。对可能产生写入、发送、删除或支付等副作用的工具：

1. 先检查 Schema；
2. 使用测试环境或安全参数；
3. 明确提示审批者；
4. 不自动重试结果未知的调用。

REST transport 默认用 HEAD 探测工具地址；HTTP 405 可表示路由不支持 HEAD，仍视为连通。可配置独立 `healthcheck_url` 用 GET 检查 2xx。健康检查不代替业务工具测试。

## 状态理解

`mode` 表示策略，`status` 表示当前运行状态，`isolation` 表示归属。三者正交，完整语义见
[状态机](../concepts/state-machine.md)。本节只保留操作层面的要点：

- `starting`：启动中；`ready`：已启动可用；`running`：存在执行中的调用；`stopped`：当前无运行实例；`failed`：连续调用或刷新失败达到设置阈值。
- **停止仅强制关闭当前实例，不修改运行策略、不阻止后续调用（INV-3）**。`lazy` / `eager` 服务在下次调用时重新拉起。
- **只有 `disabled` 才停用服务（INV-4）**：拒绝调用、跳过定时刷新、从个人资料隐藏；凭据与缓存保留。
- **业务调用不会自动重放（INV-2）**。目录不可用时，授权后的精确调用可先恢复目录、校验当前定义再执行；手动刷新、重配凭据后刷新和定时刷新也可恢复。
- 目录缓存状态与运行状态独立。未达阈值的失败保留旧目录并记录警告，不清空成功缓存时间。
- 按用户隔离时，失败计数与 `failed` 标记按 `(server_id, owner)` 归属；调用失败、工具返回 `isError`、连接失败和能力刷新失败统一计数；默认达到 3 次才将该用户作用域标记为 `failed` 并清空四类能力，阈值可在系统设置的“连续失败阈值”调整。未实际访问下游的参数校验错误、权限拒绝和已被新配置取代的操作不计为上游故障。
- 定时任务刷新所有仍有访问权的启用凭据所有者；任一次调用或完整刷新成功即清除该作用域的 `failed` 标记和连续失败计数（INV-7）；成功调用后仍可查看最近一次刷新失败的历史警告。
- 修复下游或凭据后，可通过手动刷新或等待定时刷新验证恢复。

## 删除与修改

修改连接参数会产生新的配置版本。旧实例排空后切换，避免把新调用发往过期配置。

删除服务前确认：

- 没有仍需保留的 Token 范围；
- 没有依赖该 slug 的自动化；
- OAuth 与凭据已按需要备份或撤销；
- 活动调用已经完成或可以安全取消。

删除是终态操作：级联清理所有用户的凭据、授权记录与目录缓存（INV-9），不可逆。如需临时关闭，请使用 `disabled` 而非删除。
