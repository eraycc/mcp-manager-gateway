# 服务管理与测试

## 稳定标识

每个 MCP 有显示名称和稳定 `slug`。slug 参与工具路由，创建后不应修改。需要新标识时创建副本并逐步迁移。

原始工具通常映射为 `<slug>__<tool>`；名称过长或包含特殊字符时，MMG 会生成稳定短名称。调用时始终使用搜索结果中的精确 `gateway_name`。

## 运行策略

| 模式 | 行为 |
| --- | --- |
| `lazy` | 第一次真实业务调用时启动；推荐默认值 |
| `eager` | 网关启动或具备身份上下文时预热 |
| `disabled` | 不进入可用目录，不接受业务调用 |

搜索目录和读取缓存不会为了 `lazy` 服务启动下游。

## 实例隔离

- **service**：授权用户共享实例，适合无个人状态的公共服务；
- **user**：同一用户的多个 Agent 复用，不同用户隔离；
- **session**：每个 Agent 会话独立，适合浏览器等强状态服务。

个人 OAuth 凭据和能力目录按用户隔离。不要用管理员的 OAuth 缓存替代普通用户身份。

## 添加后的发现

启用服务保存后，MMG 会运行能力发现并缓存：

- tools；
- resources；
- prompts；
- resource templates。

`lazy` 服务用于维护发现的临时实例会在完成后释放。实际 Agent 搜索读取缓存，不反复启动服务。

## 敏感字段编辑

MCP 服务和 MCP 审批共用配置编辑器。Bearer Token、密码、API Key 与 Client Secret 等字段默认使用密码输入框并以掩码显示。点击“显示敏感字段”后，编辑器会在取得授权的完整配置后把对应输入框切换为普通文本，便于核对和修改；点击“隐藏敏感字段”会重新使用密码输入框和 `[REDACTED]` 占位，未修改的密钥仍由网关安全保留。

不要在截图、日志或问题报告中暴露显示后的真实值。

## 测试

诊断应真实连接下游并读取能力。工具测试可以保存显式参数用例。对可能产生写入、发送、删除或支付等副作用的工具：

1. 先检查 Schema；
2. 使用测试环境或安全参数；
3. 明确提示审批者；
4. 不自动重试结果未知的调用。

REST transport 默认用 HEAD 探测工具地址；HTTP 405 可表示路由不支持 HEAD，仍视为连通。可配置独立 `healthcheck_url` 用 GET 检查 2xx。健康检查不代替业务工具测试。

## 状态理解

`mode` 表示策略，`status` 表示当前状态：

- `stopped`：当前无运行实例；
- `ready`：实例已连接并可调用；
- `running`：存在执行中的调用；
- `failed`：最后一次启动或发现失败。

目录缓存状态与运行状态独立。已有可用缓存时，刷新失败可以保留上一版能力并记录警告。

普通服务连续启动失败达到阈值后可能自动停止可用目录；个人 OAuth 的授权或发现失败只影响对应用户。修复配置后显式启动或恢复启用策略，再刷新验证。

## 删除与修改

修改连接参数会产生新的配置版本。旧实例排空后切换，避免把新调用发往过期配置。

删除服务前确认：

- 没有仍需保留的 Token 范围；
- 没有依赖该 slug 的自动化；
- OAuth 与凭据已按需要备份或撤销；
- 活动调用已经完成或可以安全取消。
