# 审计日志管理

[文档首页](../README.md) · [English README](../../README.md) · [中文 README](../../README.zh-CN.md) · [配置与数据目录](../operations/configuration.md)

审计日志用于追溯用户与系统对服务、令牌、权限及配置的关键操作。管理员在侧边栏“审计日志”中查询与管理；普通用户无页面和 API 访问权限。调用日志继续记录工具执行过程，两者拥有各自的列表与查询索引。

## 查看与筛选

概况显示记录数、日文件数、原文占用空间和当前保留策略。默认每页 20 条，可搜索动作、操作人、对象和安全的详情摘要，并按类别、结果筛选。“高级筛选”提供时间范围、动作、用户名称/ID、对象类型/ID、IP、操作者类型与来源。

历史事件缺少的结果显示“未知”，不会被推断成成功。用户名称和对象名称为事件时的快照；历史记录没有快照时仍保留原用户 ID 和对象 ID。详情显示事件 ID、请求 ID、来源、时间及脱敏操作详情。

导出 JSON 或 CSV 遵循当前筛选，分批流式读取；CSV 带 UTF-8 BOM 并转义电子表格公式。导出开始时固定索引上界，导出自身与之后新增的事件不进入本次结果；执行期间被删除的记录不会重新出现。导出批次会复核管理员权限。

## 删除与清空

支持删除选中、删除全部匹配和“更多操作 → 清空审计记录”。删除需要确认，并通过后台任务执行；任务开始前再次验证当前管理员身份。

提交时固定现有记录的上界，操作自身和随后新增的事件不在本次删除范围内。物理清理开始前必须先持久化并索引开始记录；索引或原文不可写时不执行清理。只重写受影响的日文件，保留其他记录；清空后的日文件会删除。完成后再记录实际影响条数与文件数。

删除通过独立的恢复日志固定目标。进程中断后，下次启动或重建审计索引会继续处理已授权的清理，避免原文和索引不一致，或重建后恢复已删除记录。开始与完成事件通过同一 operation_id 关联。

本次清理的留痕不会被本次操作带走；它们仍受未来正常的保留或清理策略管理。本地可管理审计不提供外部不可篡改存储的保证。

## 自动保留与空间回收

“系统设置 → 运行与日志 → 日志保留天数”同时控制调用日志与审计日志：

- 默认 0：无限保留，不自动删除。
- 设置为正数：保留最近相应天数的事件，按 UTC 事件时间计算年龄。
- 事件显示及日文件划分使用配置时区，文件名不作为过期边界。
- 自动清理复用现有维护周期，每小时至多执行一次；修改保留设置会请求下一轮重新应用策略。
- 有过期审计记录时，清理本身产生系统来源的 audit.clear_auto 事件。

升级保留已有设置，不自动将无限保留改为有限天数。删除记录会缩小原文文件；SQLite 数据库空闲页的物理回收仍由“存储治理”控制，详见[数据库空间治理](../database-deployment.md#数据库空间治理)。

## 存储、兼容与恢复

原文位于数据目录的 logs/audit/YYYY-MM-DD.jsonl，每行一个事件。SQLite 查询投影位于现有 indexes/logs.sqlite，拥有独立的 audit_events、扫描进度、索引迁移版本和清理恢复表；调用日志重建不会清除审计索引。

已有五字段 JSONL 无需转换，也不会因升级而改写。扫描按文件字节偏移增量执行，完整行才提交扫描进度，未完成的尾行保留到后续扫描。无法解析的历史行保持原文并计入异常记录数，不伪造成成功事件，也不会静默删除。

“更多操作 → 查看日志状态”显示写入失败、索引失败、异常记录及待恢复清理数。普通操作的审计写入失败会报告到独立运行日志与状态计数，不将已完成的业务操作改判失败。索引更新失败后原文仍保留，后续扫描或重建可恢复。

“更多操作 → 重建审计索引”仅重建审计投影。现有“重建日志索引”与 CLI 的 mmg rebuild-logs 同时重建调用和审计投影；CLI 使用运行目录锁，不能与正在使用同一数据目录的 MMG 实例并行执行。

## 关键事件与脱敏边界

当前关键覆盖包括：

| 类别 | 事件 |
| --- | --- |
| 身份 | 注册、登录成功/失败、退出、会话撤销 |
| 令牌 | 创建、修改、删除、轮换、查看密钥 |
| 用户权限 | 创建、修改、删除、角色变更、批量管理 |
| 服务 | 创建、修改、删除、显式启动/停止/刷新、启动失败 |
| 提议 | 提交、配置、批准、拒绝、删除 |
| 系统 | 设置变更、现有 OAuth/连接/存储治理与维护事件 |
| 日志管理 | 调用日志导出/删除/重建，审计导出/删除/清空/重建/自动保留 |

统一入口按事件类型限制详情字段，并在持久化前递归脱敏。令牌、密码、OAuth code/state、请求认证头及环境变量不会作为操作详情直接记录；设置记录实际变更的键及脱敏后的前后值，服务凭据仅记录变更字段，不复制配置正文。详情有大小限制，超限以明确截断标记和字段名摘要替代。

事件在明确的业务操作边界产生；请求上下文仅补充操作者、直接客户端 IP、随机请求 ID 与来源，不读取或持久化完整请求/响应体。代理来源取决于服务器已有可信代理配置，不额外信任客户端自行提供的转发头。

## 管理 API

全部接口位于 /api/v1/audit-logs，要求管理员 Cookie 会话；写操作继续使用现有 CSRF 保护。

| 方法与路径 | 行为 |
| --- | --- |
| GET / | 分页列表；page、page_size |
| GET /status | 占用、保留设置与运行诊断 |
| GET /actions | 可选动作与类别 |
| GET /export | format=json 或 csv，遵循筛选 |
| GET /{event_id} | 脱敏详情 |
| DELETE /{event_id} | 提交单条删除任务 |
| POST /delete | ids 数组；或 ids=null、filters 与 confirm=true |
| DELETE /?confirm=true | 提交清空任务 |
| POST /rebuild | 提交审计索引重建任务 |

列表和导出支持 q、action、category、user_id、username、actor_type、target_type、target_id、result、source、ip、from_time、to_time。结果为 success、failure、pending、unknown。时间参数建议使用含时区的 ISO 8601；未指定时区时按系统配置时区解析。批量明确 ID 每次最多 500 条，查询每页最多 200 条；后台任务沿用现有 jobs 查询和取消接口。
